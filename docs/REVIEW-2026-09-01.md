# Critical review — 1 September 2026

Commissioned as an adversarial review: where is this weak, where has it been
overstating itself, what is broken, what is missing. Written to be uncomfortable
rather than reassuring, because a review that flatters is useless before a
meeting.

**Headline:** the architecture is sound and the causal chain is real, but there
is one hole that partially undermines the newest and most-promoted feature, a
scaling problem that blocks the next milestone, and a standing habit of
presenting free parameters as if they were findings. Three of these were found
by Will, not by me, which is itself a finding.

---

## 1. The errors — worst first

### 1.1 CRITICAL — missions bypass the drift model entirely

**The bug.** `mission_target()` and the `World` object handed to mission scripts
are both built from `poses` — **ground truth**. So:

```python
if kind == "pursuit":
    tgt = poses.get(m.get("target"))     # <-- the TARGET'S TRUE POSITION
```

Under *total* GNSS denial, a pursuing agent still knows exactly where its target
really is. Verified live: car1 pursuing car3 with GNSS fully denied and both
agents carrying half a metre of drift still computes its target from car3's true
pose.

**Why it matters.** It contradicts the project's own locked principle, written
in `docs/history/BACKLOG.md`:

> A mission sees only what ITS OWN agent senses… A mission that can read other
> agents' sensors is cheating in a way no real vehicle can, and cheating quietly
> is worse than not working.

It is cheating quietly. Worse, it means the drift model — the feature most
promoted in the last week — only actually bites for `shuttle` objectives, where
`step()` steers from belief toward a fixed waypoint. Any objective that
references another agent silently gets perfect information.

**The honest framing for a meeting:** "position uncertainty is modelled for an
agent's own navigation, but not yet for its knowledge of others — that's the
next fix." Do **not** claim the drift model is complete.

**The fix.** An agent should know another agent's *reported belief*, and only if
a link carried it. That means: build the mission-facing world from beliefs, not
truth; gate what one agent knows about another on link state; and let stale data
persist when the link drops. This is a design piece, not a patch — it deserves
its own step and its own tests.

### 1.2 SERIOUS — the model scales as O(n³) and blocks the experiment harness

Measured on this machine:

| agents | links | ms/frame | 60 s run | 75-run sweep |
| --- | --- | --- | --- | --- |
| 4 | 10 | 0.3 | 0.2 s | 0.2 min |
| 8 | 36 | 1.9 | 1.1 s | 1.4 min |
| 16 | 136 | 13.6 | 8.2 s | 10 min |
| 24 | 300 | 46.8 | 28 s | **35 min** |

The cause is the contention counter: for every link it calls `rf_link()` once
per other agent, so cost grows with links × agents. The whole promise of the
experiment harness was "sweep it headless in seconds"; at 24 agents that promise
is already false, and the design calls for 9 configurations × formations ×
powers × seeds.

**The fix is straightforward and should happen before the harness:** compute
each agent's received power from every other agent **once per frame** (O(n²))
and have both the contention counter and the interference sum read that table,
instead of recomputing pairwise inside a per-link loop.

### 1.3 MODERATE — schema validation was blind to the live schema

`commsev/spec.py` was validating only the legacy `topology` field. `authority`,
`routing`, `leader_loss` and squad structure — all of which now change
behaviour — were unchecked, so `routing: mesg` or `leader_loss: stand` passed
silently and fell back to a default. **Fixed in this review**; typos are now
errors, and a hierarchy declared without squads raises a warning.

### 1.4 MINOR — dead code and stale pointers

- `_unused_enforce_bounds()` — 55 lines of dead function. **Removed.**
- `_scene_has_features()` checked `arena["_obstacles"]`, a key nothing ever
  sets — a dead branch whose docstring implied obstacles counted. **Removed.**
- `link_state()`'s docstring did not say it ignores jamming, the scene's noise
  floor and contention. It is clean-spectrum geometry only. **Now stated.**
- `fleets/3_roboracer.yaml` pointed at `scenes/squad_hall.yaml`, deleted weeks
  ago. **Fixed.**

## 2. Where we have been overstating

These are places where the language ran ahead of the model. Each one was caught
and corrected, but the pattern is the point: **the failure mode of this project
is confident prose around a free parameter.**

| Claim made | Reality | Status |
| --- | --- | --- |
| "GNSS jamming is theatre-wide" | It has a range like anything else; the earlier figures ignored the horizon and gave 146 km at 30 dBm | Corrected — horizon now modelled, caps at 11.7 km ground-to-ground |
| "A lidar car resists GNSS jamming" (drift = 0) | SLAM has its own drift; zero was an over-claim | Corrected to 1%/distance, sourced |
| "A lidar car localises anywhere" | A lidar needs features; in an open field it sees nothing | Corrected — aiding now requires scene features |
| Contention table presented as a finding | The coefficients (0.04, 0.6, 0.25) were **invented by me** | Corrected — now derived from airtime share and the declared QoS deadline, no fitted constant |
| Band separation as a clean defence | Real receivers leak across channels | Corrected — ACI coefficient from Zhou et al. 2020 |
| "8 drones jam each other" as SINR | In a coordinated fleet it is contention, not SINR | Corrected — modelled as airtime/collisions |

**Three of these six were caught by Will.** That is a good sign for the review
process and a bad sign for my defaults: left unchallenged, I round toward a
clean story.

## 3. What is still weak (not bugs — honest limits)

**The physical layer is deliberately coarse and must never be quoted precisely.**
- The PDR-vs-SINR curve is a logistic **stand-in**, not a modulation/coding
  curve. Trends and orderings are trustworthy; a specific PDR at a specific SINR
  is not.
- **No processing gain.** DSSS/FHSS buy a real 20–30 dB margin we do not model,
  so we *understate* a spread-spectrum radio's resilience. This is the single
  biggest gap before any "anti-jam radio" claim.
- **Omnidirectional only.** No beamforming, no directional nulling, no antenna
  patterns — an entire class of countermeasure is invisible to us.
- **No terrain masking.** Horizon is modelled; hills and buildings are not.
- **No LoS/NLoS split**, despite having the numbers (3 dB / 23 dB, Zhou et al.).

**The adversary is trivial.** One static, constant jammer. No reactive, random,
deceptive or follow-on behaviour; nothing repositions; nothing adapts. There is
no contest, so "resilience" is currently measured against a stationary threat.

**The estimator does not exist.** Drift is a scalar model with no Kalman filter
and no sensor fusion — so we can measure the *cost* of GNSS denial but have
nothing to measure a *mitigation* against.

**Behaviour over time is thinly tested.** 33 test sections, but only 5 step the
simulation more than 10 frames. Most checks are single-frame. Emergent bugs —
exactly the class that produced the drift and dynamics errors — are
under-covered.

**Nothing has been measured.** 35 of 57 declared quantities carry a source; 22
do not. Every one is declared free rather than disguised, which is the rule
working — but no RF parameter has been measured on the real hardware.

**No results exist.** Still the largest gap: the tool can show degradation but
cannot yet produce a table, a curve, or a number for a write-up.

## 4. What is genuinely strong

Stated plainly so the review is balanced, not performatively harsh.

- **The causal chain is real and, as far as the surveyed literature goes,
  unusual.** RF → link state → command authority → behaviour → position
  knowledge, in one model, with a jammer as an ordinary agent rather than a
  global flag. Network simulators model the first two stages; robotics
  simulators the fourth; little models the middle.
- **Authority separated from topology** is the strongest candidate for an
  original contribution, and it has external validation: SDN-based FANETs
  implement exactly this split (centralized control plane, distributed data
  plane), and it echoes standing military doctrine (centralized control,
  decentralized execution).
- **The provenance discipline is unusual for research code** and is what
  allowed this review to enumerate every free parameter in one table.
- **The three-layer file model** (scene / fleet / mission) is clean, diffable
  and makes experiments reproducible by construction.
- **166 tests**, and every bug found in the last week has a regression test.

## 7. Priorities coming out of this review

1. **Fix the mission/belief hole (§1.1).** It undermines the drift model and
   contradicts a stated principle. Nothing else should be built first.
2. **Fix the O(n³) scaling (§1.2)** — required before the experiment harness is
   worth building.
3. **Build the experiment harness.** Still the difference between a demo and a
   dissertation.
4. Deepen behaviour-over-time testing while doing 1–3.
5. Then: Mission Command authority, quadcopter, formation axis.

## 8. Speaking about this in a meeting

**The one-sentence version.** "It's a testbed for what jamming does to a command
structure — it carries a radio effect through to who can still be ordered, what
a cut-off vehicle does about it, and whether it still knows where it is."

**The claim to make.** Comparative: *under identical conditions, architecture A
retained command over more of the fleet than architecture B.* Never absolute
performance numbers.

**If asked "is the RF model realistic?"** — "It's a defensible abstraction, not a
fidelity model. Path loss and SINR are standard and independently match the
published multi-UAV formulation; the packet-delivery curve is an honest
stand-in. We don't model spread-spectrum processing gain, so we understate
anti-jam radios. Every free parameter is declared."

**If asked "what's novel?"** — "Separating decision authority from network
topology and measuring the gap. A mesh survives its hub dying; the
decision-making doesn't. SDN networks make the same split, and it mirrors
mission-command doctrine, but I haven't found it isolated and measured in
simulation."

**If asked "what are the weaknesses?"** — lead with §1.1 and §3. Volunteering
them is far stronger than being caught by them, and the provenance register
means you can answer any "where did that number come from?" instantly.

**If asked "what results do you have?"** — the honest answer today is *none yet*:
the mechanism is built and tested, the measurement harness is next. Do not
improvise a number.
